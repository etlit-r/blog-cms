# review-until-clean

`/code-review` を実行し、指摘があれば修正して再レビューする、を指摘が 0 件になるまで繰り返す。

## 引数

`$ARGUMENTS` はそのまま `code-review` スキルに渡す（例: `high`、`medium 123`、`src/`）。
空なら引数なしで呼ぶ（`code-review` 側の既定レベルが使われる）。
`--fix` / `--comment` は利用者が書いていても渡さない（修正はこのスキル側で行うため）。

## 手順

最大繰り返し回数 `MAX = 10`。`round = 1` から始める。

1. **レビュー**: Skill ツールで `code-review` を呼ぶ（args = `$ARGUMENTS`）。
   - 結果の指摘一覧を記録する（ファイル・行・要約）。
2. **終了判定**:
   - 指摘が 0 件 → 「round 回目で指摘なし」として終了し、最終報告へ。
   - `round == MAX` → 打ち切って最終報告へ（残った指摘を必ず列挙する）。
3. **修正**: 今回の指摘をすべて修正する。
   - 誤検知と判断したものは修正せず、理由を記録する。次のラウンド以降に同じ指摘が再度出ても、
     それだけが残っている場合は「実質 0 件」とみなして終了してよい（無限に揉めないため）。
   - 修正後、プロジェクトにテスト・型チェック・lint があれば実行し、壊していないことを確認する。
     失敗したら、そのラウンド内で直してから次へ進む。
4. `round += 1` して 1 に戻る。

各ラウンドの終わりに 1 行だけ進捗を出す（例: `Round 3/10: 指摘 2 件 → 2 件修正`）。

## 注意

- コミット・プッシュは利用者に頼まれた場合だけ行う。ラウンドごとに自動コミットしない。
- 同じ指摘が 2 ラウンド連続で修正しても消えない場合は、修正方針を変えるか誤検知として扱い、
  ループを空回りさせない。
- テストを無効化・スキップして指摘や失敗を消してはいけない。

## 最終報告

次をまとめて報告する:

- 実行ラウンド数と終了理由（指摘 0 件 / 10 回で打ち切り / 誤検知のみ残存）
- ラウンドごとの指摘数と修正内容の要約
- 修正しなかった指摘とその理由（誤検知判断・打ち切りで残ったもの）
- テスト等の実行結果
